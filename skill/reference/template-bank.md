# Template bank – every layout in template.pptx

Generated by `maintenance/build_template_bank.py` from `template.pptx` + `tokens.json` (geometry,
background, placeholders, capacity, guide examples) and its curated purpose/signal table. Machine-readable:
`reference/template-bank.json` (read by `scripts/matcher.py`). Do not edit by hand. This is the template bank:
the amasol style guide's own 50 layouts are the only layouts a deck may use.

## Contents
1. How the matcher uses the bank
2. Structural layouts (cover, agenda, dividers, quotes, key slides, closings)
3. Content layouts by family
4. Placeholder capacity per layout (idx type size lines×chars)

## 1. How the matcher uses the bank
* **Role** fixes where a layout may stand: `cover` first, `agenda` second, one `divider` before each
  chapter, `content`/`key`/`quote` for planned slides, `closing` last.
* **Visuals** = what a layout can host; a plan entry's `visual` must be in its layout's list.
* **Family** = background. Content slides use one family (RULES §10; default Weiß, where `Inhalt &
  Infobox`, `Inhalt & Tracker` and `Bild & Diagramm` also count as white). There is no white `Inhalt &
  Diagramm` and no white image layout: charts on Weiß go on `Inhalt & Tracker`, `Inhalt - Weiß` or `2 Inhalte -
  Weiß`; a body+photo slide needs the Rosa or Blau family (`Inhalt & Bild - Rosa`, `Inhalt, Bild & Form -
  Blau`), otherwise the photo goes into a `story_panel(picture=)` on `2 Inhalte - <family>`.
* **Rank** = preference among layouts that fit (0 first); the matcher also avoids repeating the previous
  layout and keeps each layout within max(2, ⌈2n/12⌉) uses (RULES §11).
* **Picture** = side of the picture placeholder (left/right/full) – image-left vs image-right.
